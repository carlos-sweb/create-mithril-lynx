## Performance & Splash Screen

Android projects generated by this template use `MULTI_THREADS` and a native
hybrid splash placeholder. The system splash hands off to an identical native
view while Lynx renders its first frame, then fades away once the `loadBundle`
pipeline is ready (with safe timeouts as fallbacks).

Keep startup light: avoid importing heavy libraries such as Zod or Numeral on
the initial route. Prefer small JavaScript validation functions and
deterministic formatting helpers. Assets above 4 KiB are not inlined in the JS
bundle (`dataUriLimit: 4096`).

> Rendimiento: los builds Debug no representan el rendimiento de producto. Mide arranques en frío y tamaño de APK sólo con `npm run android:release` firmado; Debug conserva instrumentación y desoptimización adicionales.

> Android permite `usesCleartextTraffic="true"` para desarrollo local. Desactívalo antes de publicar si la app no requiere HTTP.

## Learn more

- `src/main-thread.ts` starts the main-thread patch-replay runtime (`setupRenderer()`) — mithril-lynx has exactly one rendering mode, so no app code lives here.
- `src/background.ts` is where the app actually mounts (`renderApp()`), running the real Mithril view tree in the background thread.
- Everything about the framework — the three reload modes, routing, networking — is documented in [`mithril-lynx`'s own README](https://github.com/carlos-sweb/mithril-lynx#readme).
